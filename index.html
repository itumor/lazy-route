02

Three strategies. One guarantee.

The routing decision must never be the reason your session dies. Pick how smart the brain is — the fallback is always local.

heuristic

offline · deterministic · 0ms network

A pure, unit-tested scoring policy over 15 questionnaire signals. No network, no keys, no surprises. Runs even when the internet doesn't.

jev

any OpenAI-compatible endpoint

Send the questionnaire to a real LLM — a hosted router model, or a local Ollama / LM Studio / llama.cpp box. You choose the brain; you choose its URL.

DEFAULT

chain

jev, with heuristic fallback

Best of both: LLM-judged routing when available, instant deterministic fallback the moment anything fails. Your session never notices.

?!

Why a sidecar and not an MCP server?

Because MCP tools run after a model was already selected — too late to choose the model. lazy-route must decide before execution, so interception lives in the request path: a loopback proxy for Claude & Codex, an in-band waterfall for DeepSeek Harness. Plugins, MCP tools, and skills sit on top purely as UX — /jev-status, /jev-explain, jev_route.

03

The ladder: 4 tiers × 5 efforts

A weighted aggregate score with calibrated thresholds picks the tier; effort clamps from tier index plus execution-depth adjustments. High-stakes or novel work is force-lifted upward.

CAPABILITY TIERS
haikuSimple, deterministic, low-risk. Extraction, classification, formatting, straightforward transforms, simple file ops.
sonnetNormal production work. Software development, standard debugging, research, multi-tool agentic workflows.
opusDeep reasoning & judgment. Difficult debugging, architecture, unfamiliar systems, high-risk changes, subtle trade-offs.
fableExceptional & long-horizon. Sustained reasoning, complex planning, extensive state tracking, frontier problems.

Effort is the second axis: the lowest level likely to complete the task reliably — raised only when extra reasoning depth will materially improve the result. Merged into the upstream request as thinking params unless your client already sets them. Client-sent thinking blocks are preserved by design.

Every tier maps to a concrete model — and every map is yours to override

04

Plugs into the agents you already use

No fork, no wrapper SDK, no changed workflow. The router appears as just another model in the picker you already have.

● shipped — verified against claude 2.1.278

Claude Code CLI

Launch jev-claude and the daemon spawns itself if needed. A "JEV Router" model option appears in the picker — select it once, every turn routes.

node adapters/claude-cli/jev-claude.mjs
● shipped — local sessions

Claude Code Desktop

A settings installer patches your env block (with backup and dry-run) — then pick "JEV Router" in the Desktop Code tab. Nothing else changes.

node adapters/claude-desktop/install.mjs --dry-run
● shipped

Codex CLI

One routing decision per launch: the prompt is classified, then Codex starts on the resolved model. Step-behind simplicity, zero in-band plumbing.

jev-codex "migrate the test suite to vitest"
● shipped — in-band waterfall

DeepSeek Harness

A dynamic Cordis plugin: a jev_route tool and a subagent routing table, interception inside the request waterfall rather than a proxy.

adapters/dsh/jev-dsh.plugin.mjs
05

Paranoid by default

It's a proxy, so it could see everything. It's built so it effectively doesn't — and the tests enforce it.

OK

Loopback only

The daemon binds 127.0.0.1 by default. Nothing listens on your network unless you explicitly say so.

OK

Credentials forwarded, never stored

authorization / x-api-key pass through byte-identically and are never logged — enforced by tests, not by promises.

OK

Secrets redacted

JEV_API_KEY lives in env or config only; /jev/status shows "***" when set. Never committed, never echoed.

OK

Zero dependencies, fully offline capable

Node ≥ 20 builtins and global fetch only. Run JEV_STRATEGY=heuristic and nothing leaves your machine but the model calls you already make.
